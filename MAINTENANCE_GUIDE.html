How It Works

The system processes WordPress sites through a structured workflow with three phases: setup (load sites), maintenance (process each site sequentially), and summary (report results).

Execution Timeline Per Site

1️⃣ Health Check (Initial) — Verify site responds └─ 60s wait 2️⃣ Check Updates — Count available plugin & core updates └─ 60s wait 3️⃣ Update Plugins [IF plugins_available > 0] ├─ Queue plugin update batch ├─ [IF no backup] Create backup + retry └─ 60s wait 3a. Monitor Plugin Batch [IF batch_id valid] ├─ Check status every 120s (max 5 checks = ~10 min timeout) └─ 60s wait 3b. Send Plugin Report Email 4️⃣ Update WordPress Core [IF core_available == true] ├─ Queue core update batch └─ 60s wait 4a. Monitor Core Batch [IF batch_id valid] ├─ Check status every 120s (max 5 checks) 5️⃣ Final Health Check — Verify site still healthy 6️⃣ Check External Updates — 3rd-party dependencies [RETRY 3x] 7️⃣ Sync to Google Sheets — Write results [RETRY 3x] 8️⃣ Send Site Report Email — Email summary to team
Timing: ~4-7 hours for 10 sites. Each site 30-45 min (includes mandatory 60s waits between steps and 120s batch monitoring intervals).

MCP Tools Reference

The workflow calls these tools dynamically. Claude selects the right tool based on what each step needs to accomplish.

Health & Status

MCP Tool
health-check-tool
Check if site is healthy
Params: id (site_id) | Returns: {status, errors}
MCP Tool
check-updates-tool
Count available updates
Params: id | Returns: {plugins_available, core_available, core_version}

Updates

MCP Tool
update-all-plugins-tool
Update all plugins at once
Params: id, create_backup, run_health_checks | Returns: {batch_id, status, plugins_updated}
MCP Tool
update-core-tool
Update WordPress core
Params: id, version, create_backup, run_health_checks | Returns: {batch_id, status, target_version}

Batch Operations & Monitoring

MCP Tool
check-batch-status-tool
Monitor job progress (called every 120s)
Params: id, batch_id | Returns: {status, completed_count, total_count, jobs_summary}

Data & Reporting

MCP Tool
sync-sheets-tool
Write results to Google Sheets
Params: id | Returns: {synced, message, row}
MCP Tool
check-external-updates-tool
Check for non-WordPress updates
Params: id | Returns: {found_external, updates}

Backups & Recovery

MCP Tool
create-backup-tool
Create site backup before updates
Params: id, backup_type | Returns: {success, backup_id}
MCP Tool
rollback-tool
Revert to previous backup
Params: id, backup_id | Returns: {success, message}

Utilities

MCP Tool
site-info-tool
Get site details
Params: id | Returns: {site_id, url, wp_version, plugins_count, theme}
MCP Tool
who-am-i-tool
Verify MCP server connected
Params: none | Returns: {authenticated, user, permissions}

Architecture

Component Location Purpose
Workflow .claude/workflows/daily-maintenance.js Orchestrates entire process, calls agents per step
Sites Loader Agent .claude/agents/sites-loader.md Only custom agent; runs Python script to load sites
Inline Agents In workflow file Each step calls agent; Claude picks right MCP tool
Python Helpers get_today_sites.py, send_email.py Load sites from Google Sheets, send emails via SMTP
Logs log/maintenance_logs/ JSON files per site: site_SITEID.json
Config .env Secrets: API keys, SMTP, Google Sheet ID

Design Principles

  • Dynamic Tool Selection: Workflow describes goals; Claude picks appropriate MCP tool
  • Sequential Processing: Sites processed one at a time (prevents overload)
  • Strict Intervals: 60s between steps, 120s between batch checks (prevents rate-limiting)
  • Conditional Logic: Plugin/core updates only run if updates exist
  • Retry Logic: External checks & sheet sync retry up to 3 times on failure
  • Comprehensive Logging: Every step logged to JSON + email reports sent

Troubleshooting

❌ "No sites found for today"

Check: Google Sheet tab exists for today's day name (exact match: "Monday", not "monday"). Column A has URLs. Tab is shared with service account.

Test: python get_today_sites.py

❌ Email reports not sent

Check: SMTP credentials in .env are valid. Using app password (not regular Gmail password). send_email.py actually called (not just HTML composed).

Test: python test_email.py

❌ Plugin/core updates not running

Check: Update check returned 0 plugins or false for core (correct behavior). Agent actually called MCP tool (check transcript).

Look for: "MUST CALL: update-all-plugins-tool" in transcript

❌ Batch monitoring timeout

Check: Batch job actually queued (has valid batch_id). Job is running (not stuck at "pending").

Fix: Reduce MAX_BATCH_CHECKS to fail faster if needed

❌ Sheet sync failing after retries

Check: Google Sheets API quota. Sheet structure matches expected columns. No formula errors in update cells.

Verify: Open sheet in browser, check for red error triangles

❌ "Authentication failed" for MCP tools

Check: MCP server is authenticated. Service account file exists. Credentials in .env valid.

Fix: Reconnect MCP server in Claude Code: /mcp smartsites-maintenance

FAQ

How long does a full run take?

~4-7 hours for 10 sites. Per site: 30-45 min (includes required waits between steps).

Can I run multiple sites in parallel?

Not currently. Sequential processing prevents rate-limiting and keeps logs clean. Future feature.

What if a site fails?

Error logged to that site's JSON file. Workflow continues to next site. Daily summary shows which sites failed.

Can I monitor progress in real-time?

Yes. Run in Claude Code interactive, watch progress tree, click agents to see transcripts, or check log/maintenance_logs/ in real-time.

What happens if interrupted?

Partial logs saved. Emails may sent for completed sites. Run again to finish.

How do I add a new site?

Open Google Sheet → Find tab for day → Add row with URL, Site ID, etc. → Save. Picked up automatically on next run.

How do I disable a site?

Delete row from tab or move to "Disabled" tab. Site skipped on next run.

Can I manually trigger a batch job?

Yes. Use update-all-plugins-tool directly via Claude Code, monitor with check-batch-status-tool.
